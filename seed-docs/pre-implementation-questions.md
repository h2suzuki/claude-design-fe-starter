# 実装前ヒアリング — mock に写らないことを聞く

mock は「何がどう見えるか」の正本だが、**「どれだけあるか・どれだけ待つか・どこから来るか」は写らない**。実装に入ってから聞くと作り直しになるので、画面の実装を始める前に一度で聞く。

聞く相手は発注側（画面の使われ方を知っている人）。答えは発注書か PR 説明に残し、`screen-loop.md ④` の完了条件にする。

**機械で分かることは聞かない。** mock 自身の破れ（横スクロール・はみ出し・重なり・文言や token の割れ）は凍結時の検査で出す（`docs/presentation/ui-mock/README.md` の凍結手順）。ヒアリングは人しか知らないことに絞る。

## 初回のみ（walking skeleton で 1 度）

**外部依存**

- 地図・動画・SNS の埋め込みはあるか。遮断された環境では何を見せるか
- 外部が落ちているとき、画面全体を止めるか、その領域だけ畳むか

> 埋め込みは export の閉包に入らない。mock 側も実装側も同じく空になるので、parity は通ってしまう。

**権限と出し分け**

- ログイン状態や role で表示が変わるか。mock はそのうちどの状態を描いているか

> mock は 1 つの状態しか描かない。描かれていない状態は「無い」のか「描いていないだけ」なのか、mock からは区別できない。

**遷移と保持**

- 戻ったときにスクロール位置・入力・選択を保つか

## 画面ごと（実装に入る前）

**重い資産** — 先に `npm --prefix pp run lint:mock` を回し、MOCK104 が挙げた資産と合計サイズを出す。**そのうえで、下の既定の処置を添えて聞く**

聞き方は「どうしますか」ではなく「**こうします、それでよいですか**」。処置は決まっているので、確認するのは意匠に触る部分だけ。

- この処置でよいか。**落とせない画質の下限**があるもの（意匠上、粗くしてはいけないもの）はどれか
- 先読みを外した方がよいものはあるか（従量課金の回線が主・滅多に開かない）
- **承認を得るまで実装に入らない**

> **どれが重いかは聞かない — 測れば分かる。** 実測例: ある PJ の凍結 export は 18 file / 23.11 MB、うち 8 file が 1 MB 超（最大 4.05 MB、ロゴでさえ 1.29 MB）。JPEG 化で 14.1 MB → 1.74 MB、開いた 300ms 後の先読みでクリックから表示まで 35〜70ms になった。

**ネットワークが多くなる箇所** — mock を読んで挙げ、**対策の承認を得る（必須）**

- 月送りのあるカレンダー、無限スクロール、絞り込みのたびに取り直す一覧、地図、検索候補 — **mock を見れば、実装すると何回取りに行くかは分かる**。目星は `③ AST 抽出` で木を読み切る過程でも付く
- 箇所ごとに **「何が重いか / どう対策するか」を組にして示す**。対策の既定は「まとめて取る」「先に取る」「遅らせる（見えたときに取る）」
- **承認を得るまで実装に入らない。** 対策は実装の形そのものを決めるので、後から変えると書き直しになる

> 部品の数は大抵問題にならない。効くのは**取りに行く回数**。実装するのも mock を読むのも同じ LLM なので、「見ただけでは分からない」は成り立たない。

**量**

- リストや表は実際に何件並ぶか。「多い」のは何件からか
- 文字列の実際の最大長はどれくらいか（人名・住所・名称）
- 空になることはあるか

> mock が描くのは数件・短い文字列の「見本」で、実データの分布ではない。件数と長さは、折り返し・省略・スクロールの設計を変える。

**状態の実際**

- 空・エラー・読み込み中は実際どのくらいの頻度で起きるか
- 読み込みが長引いたとき、待たせるか、部分的に見せるか

> mock には全状態が並ぶが、頻度は描かれない。滅多に出ない状態と常時出る状態では、置く場所も作り込みも変わる。

**入力（入力がある画面のみ）**

- 必須・形式・上限の規則
- 送信に失敗したとき、入力した内容を保つか

> mock が描くのは error 状態の**見た目**であって、何が error なのかの規則ではない。

## 重い資産の既定の処置

MOCK104 が挙げた資産には、**聞く前からこの処置を当てる**。ヒアリングは外すかどうかの確認であって、当てるかどうかの相談ではない。

1. **写真は JPEG 化する**（透過が要るものは WebP）。PNG のままにするのは、線画・ロゴ・透過が必要なものだけ
2. **表示寸法に合わせて解像度を落とす**。基準幅での表示寸法の 2 倍を上限の目安にする（それ以上は画面に出ない情報）
3. **先読みする**。画面を開いた時点で裏で読み、操作されたときには読み終わっている状態にする
4. **十分小さいものは data URI で埋め込む**。リクエストそのものを無くす（目安 8 KB 以下。埋め込むと HTML が肥大するので上限を超えたら 1〜3 に戻る）

外した項目は、理由を添えて日付付きで PR 説明に残す。

## 書き方

- **答えが「決まっていない」なら、そう書く。** 空欄のままにすると、実装が既定値を勝手に決めて既成事実になる
- 数値は数値で受け取る（「速く」ではなく「クリックから 100ms 以内」）。後から検証できる形にする
- 発注側が判断できない項目（技術的な選択肢が要るもの）は、選択肢と各々の帰結を添えて聞き直す
