# DESIGN-POLICY — KEEP_IMPL 台帳

mock と実装の**意図的な**差分を記録する台帳。差分を黙認する一覧ではない。

- エントリの追加・意味変更・削除には日付付きのユーザー裁定を必須とする
- 台帳にない mock/app 差分は欠陥として扱う: 実装を直すか、確定済みの実装表示を mock へ鏡映して push back する（`docs/design-sync.md`）
- parity テストが登録済み差分を吸収する機構は**まだ無い**。台帳に entry がある間、その差分は parity で赤のまま残る。まず mock を直して解消し、直せない事情がある差分に当たった時点で機構を作る（`docs/pixel-perfect.md`）
- **既定の処置に従った画像の軽量化は載せない**（`seed-docs/pre-implementation-questions.md`）。`page-parity` は画像の中身を見ないので差分にならず、意匠の差でもない。載せるのは、承認時に「粗くしてはいけない」と決めた画像を落とした場合だけ
- 台帳は「mock へ還流待ちのバッファ」であり、恒久の例外リストではない。対象画面の mock を更新する機会には entry を走査し、裁定内容を mock へ反映して entry を閉じる（削除の経緯は commit message に日付付きで残す）。定常状態は縮小方向 — entry の滞留は mock と実装の乖離を固定化する
