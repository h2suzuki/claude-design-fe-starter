# DESIGN-POLICY — KEEP_IMPL 台帳

mock と実装の**意図的な**差分を記録する台帳。差分を黙認する一覧ではない。

- エントリの追加・意味変更・削除には日付付きのユーザー裁定を必須とする
- 台帳にない mock/app 差分は欠陥として扱う: 実装を直すか、確定済みの実装表示を mock へ鏡映して push back する（`docs/design-sync.md`）
- **対象列は 3 つの形のどれかで名指しする。** 散文で書くと gate は 1 行も読まないので、差分は落ち続け、台帳は効かない。読めない書式は `keep-impl` の spec が名指しで落とす

  | 書き方 | 効く gate | 外れるもの |
  | --- | --- | --- |
  | `img: <src の一部>` | `page-parity` | その画像の**中身**だけ（置かれ方＝枚数と箱は常に比較される） |
  | `style: <visual id>/<prop>` | `sample-parity` | その部品のその style property だけ |
  | `geometry: <visual id>/<axis>` | `sample-parity` | その部品のその軸（x / y / width / height）だけ |

- **画像だけ部分一致、id と prop は完全一致**。`style: hero` と書いても `hero-badge` は外れない — 前方一致にすると隣の部品まで黙って通るため
- **`img:` は file を名指しする。dir では書かない。** 部分一致なので `img: assets/` はその配下すべてに当たり、台帳を書いていないのと同じ状態（全画像が素通し）になる。`/` で終わる対象は spec が落とす。画像が多い画面では行数が増えるが、1 行にまとめると承認していない差し替えまで通る
- 台帳に無い差分は落ちる — 承認していない差し替えを見逃さないため
- **既定の処置に従った画像の軽量化も載せる**（`seed-docs/pre-implementation-questions.md`）。承認を得た事実と対象が台帳に残り、gate はそれを読んで除外する。載せないと parity で落ち続け、載せずに gate を緩めると承認していない差し替えまで通る
- 台帳は「mock へ還流待ちのバッファ」であり、恒久の例外リストではない。対象画面の mock を更新する機会には entry を走査し、裁定内容を mock へ反映して entry を閉じる（削除の経緯は commit message に日付付きで残す）。定常状態は縮小方向 — entry の滞留は mock と実装の乖離を固定化する
